# Support registry: open findings

Defects and open questions found while converting the support system to derive
from `src/supports/supportTypeRegistry.ts`. **Only live items are here.**

Resolved findings are archived outside the repo. A handful of fixed ones stay
below, in *Lessons*, because they changed how work here is verified.

**Status values.** `open` is a live defect or an undecided question.
`recheck` tests clean but changes visible behaviour, so it wants a second pair
of eyes. `partly fixed` means the seam landed and call sites remain.

**Record who decided, and on what evidence.** An entry with neither is not a
decision -- mark it open. A previous revision closed a finding on
"confirmed by the owner" with no such confirmation on record, and every later
pass then skipped it deliberately.

## Lessons (fixed, but they changed how we verify)

These are resolved. Each one names a check that looks sufficient and is not, so
the rule is the point and the case is the evidence for it.

| rule | evidence | where |
| --- | --- | --- |
| **A type drawn only by its own detail renderer is reachable by no batched overlay.** Anything that highlights by re-drawing batched sources silently skips it. | A marquee drag showed every type lighting up except brace and stump: the preview is four instanced overlay sources, reaching only types declaring `batchesShaft`, `batchesContactCones` or `ownsRoot`. Brace and stump declare none. A second route through the detail renderer was needed -- and the renderer's own dim gate then overwrote the colour unless it was also told the support counted as selected. | fixed -- `typeHasBatchedMarqueeOverlay` and `supportIsDrawnSelected`, mutation-tested |
| **A slot filled by self-registration needs a load-time assertion that it was filled.** A module nothing imports never runs, so the registration never happens and the slot reads as legitimately empty. | Three anatomy previews registered nothing and fell through to the trunk diagram. No test and no golden saw it: the map was empty and `hasOwnAnatomyPreview` honestly reported `false`. Second occurrence of this shape. | `anatomyPreviewRegistry.ts`; asserted like `collectionsMissingRestore()` and `typesMissingExportGroupBuilder()` |
| **Deriving a fact removes a drift risk and adds an execution-order risk.** The second kind fails silently. | The registration barrel must load before the generic pass that fills empty slots, or the generic one claims them all. | `state.ts` updater registration |
| **A conceded folder's *exports* are not conceded.** A type's own folder may name itself in values; a TYPE it exports carrying its own name breaks every consumer on a rename. | `BranchBuildResult = { branch: Branch & { typeId: 'branch' } }` is exempt as a site, but a rename makes the literal invalid, the intersection becomes an error type, and consumers fail. Measured: 12 autoPlace errors became 20, 8 of them phantom `TS2339` on properties that exist. | `SupportTypes/Branch/branchBuilder.ts` and any result type like it — **open constraint on the rule** |
| **A hand-written union of type ids survives a rename with no error.** A rename test cannot see this class, so a union needs a negative case, not a green suite. | `KickstandHostKind = 'trunk' \| 'branch'` and three `typeId:` variants in `state.ts` renamed clean. | fixed — derived from `hostsKickstand` and `JOINT_REMOVAL_BY_TYPE`; `derivedTypeSubsets.test.ts` holds each map to its flag with `@ts-expect-error` negatives |
| **`npx tsc --noEmit` under-reports when an incremental build exists.** Use `-p tsconfig.json`, and treat a suspiciously clean run as unverified. | Twice a plain run printed nothing while `-p tsconfig.json` reported real errors in the same tree: once a missing import, once an undeclared identifier plus two type errors. Neither the suite nor the goldens would catch it — they run through `tsx`, not `tsc`. | repo-wide — **open, process not code** |
| **Deriving *what* a memo reads without deriving *what it depends on*** leaves the index stale. | Three snap-target memos asked for `ALL_SNAP_TYPES` while listing collections by hand, so a green preview could fail to commit. The hand-written arrays were already raising `exhaustive-deps` warnings nobody acted on. | fixed — depend on `supportState` itself, which ESLint can verify |
| **A walk that names its collections by hand omits the type with no edges.** The type with an inline root and no edges appears in no id-remapping list and is the easiest to forget. | Clipboard capture walked the registry, but the merge and its gate named eight collections by hand and omitted one — a model supported only by that type pasted nothing. Reported by a user. | fixed — merge and count derive from `SUPPORT_COLLECTION_KEYS`; the mutation reinstating the skip fails both tests |
| **The same omission shape recurs; sweep for it rather than waiting for a report.** | Two more hand-typed walks: `resolveSupportModelId`'s seven-branch chain (latent — callers pass `entity.modelId` first, so it short-circuited) and `DiagnosticsModal`'s three hand-kept collection lists. | fixed — the resolver walks `SUPPORT_TYPES` then declared `hostedBy` edges; equivalence checked over 17 fixture ids across all eight types |
| **An export path can drop a whole type while every test passes.** A test asserting nothing *wrong* is present is satisfied by a type being absent. | Dropping a type from `buildScopedSupportGeometryGroup` left all tests green; the assertion was `children.length > 0` plus a modelId filter. | fixed — expected group-name prefixes derive from each descriptor's `singular`, so a new type is covered by being declared |

| **A second per-type `State` interface threaded beside the shared one is a duplicate, not a seam.** | `KickstandState` was the only one in the codebase, threaded through five functions across three modules. | **A purge that names its collection while the generation beside it walks the registry will miss the next type.** | Auto-bracing's stabiliser purge read `rootId`/`hostKnotId` directly; a second stabiliser type would be generated and never purged. | **A duplicate walk can be harmless in output and still be wasted work.** | The slice path built raft base circles twice from the same snapshot; `computeFootprint` unions them, so no geometry changed and the slice goldens were unchanged, but every export paid for it. | fixed — found because the name promised a filtered set the value never was |
| **A field cloned into history that nothing reads still costs every transform.** | `kickstandState` was `structuredClone`d into undo/redo on every transform beside a `supportState` that already contained the kickstands. | Shaft stub length was 10 for trunk and 5 elsewhere, with four other sites hardcoding 10. | Behaviour change, reached only when a shaft has no top joint and no contact; all goldens unchanged. | fixed — `resolveSegmentEndpoints` reads `shaftFallback.stubLengthMm` |
